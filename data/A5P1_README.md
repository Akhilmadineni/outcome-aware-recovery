# A5P1 - Outcome-aware recovery under ambiguous API responses

**Track:** Track 2  
**Application:** Cloud deployments for EV charging-network backends

> This dataset is synthetic, generated by gen_author5.py with seed 2077. It must be described as synthetic in any publication.

## Simulated scenario

Deployment pipelines for an EV charging-network backend (OCPP gateway, billing, charger status, reservations) call cloud control-plane APIs. Each row is a call that ended ambiguously (timeout, 5xx, 409, 202 without status, connection reset). The deployer sees the response, timing, retries and reconciliation evidence (describe calls, async status, audit log, tags) which may be stale because of eventual consistency. Ground truth is whether the change actually took effect and the correct recovery action - the inputs an outcome-aware recovery engine needs.

## How it was generated

- Response classes drawn from a fixed mix; control-plane congestion is a Beta variable with evening peak, provider effect and a 30-day cycle.
- P(applied) = sigmoid(response-class base + elapsed/timeout + async + idempotent retries + provider - congestion x 500); partial application more likely for slow async ops under congestion; duplicates arise from retries without idempotency keys.
- Reconciliation evidence is generated from the true outcome with eventual-consistency lag (describe visibility = sigmoid of poll delay vs lag), noisy async status, audit log with 3% false positives.
- correct_recovery_action is a deterministic function of the true outcome and operation duration.
- Noise: 5% Gaussian, ~0.7% outliers (elapsed, payload, audit lag), 1-3% missing (audit lag, payload, congestion).

## Suggested experiments

1. Outcome inference: classify true_outcome from response + evidence (macro-F1, per-class recall); baseline = 'treat every ambiguous response as failure and retry'.
2. Recovery policy evaluation: simulate executing the predicted recovery action and count resulting duplicates, orphaned resources and extra deployment minutes vs blind-retry and always-poll policies.
3. Value of evidence: ablate describe/audit/tag evidence and measure accuracy vs added reconciliation latency (poll delay).
4. Calibration under congestion: report ECE stratified by control_plane_congestion quartiles.

- All IDs, sites, regions and assets are synthetic; no real people, companies, IPs or CVEs.
